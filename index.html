§01 — Track A
A

Track A · Engineering

Systems that do the work

Small companies run on a handful of critical systems. We build them to be understood, maintained, and handed over — not just shipped.

T-01

Computer-aided dispatch (CAD) systems

Dispatch software sized for small operators — patient transfer services, couriers, field crews. Take a request, assign it, track it to done, and keep a record of every step.

  • Request intake, assignment, and live status board
  • Separate views for dispatchers, crews, and supervisors
  • Time-stamped history for every job

Case studies

Placeholder Dispatch board for a non-emergency patient transfer service CAD · Web app · Audit trail
Problem
Transfer requests came in by phone and lived in a shared spreadsheet. Nobody had one view of which crew was where.
Approach
A web dispatch board with request intake, crew status, drag-to-assign, and role-based views for dispatch and supervisors.
Outcome
One live board replaced the spreadsheet, and every transfer carries a time-stamped history.
Stack
Python, PostgreSQL, server-rendered UI
T-02

Database design & build

Schemas that match how your business actually works. We move your data out of spreadsheets and inboxes into a database you can query, back up, and trust.

  • Data modeling, schema design, and migration
  • Backups with a tested restore procedure
  • Plain-language documentation of every table

Case studies

Placeholder Consolidating customer and job records for a field-service company Schema design · Migration · Backups
Problem
Customer details, quotes, and job history were split across several spreadsheets with no shared IDs.
Approach
Modeled the business entities, cleaned and de-duplicated the source data, and migrated it into a relational schema with constraints.
Outcome
One source of truth for customers and jobs, with nightly backups and a documented restore.
Stack
PostgreSQL, Python migration scripts
T-03

VPS links between systems & databases

Your main system needs to reach its database without exposing it to the internet. We set up a hardened VPS and an encrypted private link between them.

  • Hardened VPS build with firewall allow-lists
  • Encrypted tunnel — no public database port
  • Monitoring and a written runbook for the link

Case studies

Placeholder Private link between an office application and a hosted database VPS · WireGuard · Firewall
Problem
The database accepted connections from the public internet so the office application could reach it.
Approach
Built a hardened VPS, connected the office system over an encrypted tunnel, and closed the database to everything but the tunnel.
Outcome
The database is no longer publicly reachable, and the team has a runbook for the link.
Stack
Linux VPS, WireGuard, host firewall
§02 — Track B
B

Track B · Cybersecurity

Defenses you can show an auditor

Visibility, least privilege, and controls mapped to recognized standards. Every engagement ends with evidence you can hand to a customer, insurer, or auditor.

S-01

SIEM

Security information and event management. We pull logs from the systems that matter into one place and tune alerts so the ones that fire are worth reading.

  • Log source onboarding and normalization
  • Detection rules tuned to your environment
  • Alert routing and a triage playbook

Case studies

Placeholder Centralized logging and alerting for a multi-site office SIEM · Detection · Playbooks
Problem
Logs stayed on each server and firewall. Nobody would have noticed a failed-login spike until something broke.
Approach
Deployed an open-source SIEM, onboarded servers, firewalls, and identity logs, and wrote rules for the events the team cared about.
Outcome
One console for security events, with alerts routed to the right person and a playbook for each.
Stack
Wazuh, syslog, Windows event forwarding
S-02

Cloud infrastructure

Cloud environments built as code, so they can be reviewed, rebuilt, and audited. No mystery resources, no hand-clicked production.

  • Infrastructure-as-code for networks, compute, and storage
  • Separate environments for testing and production
  • Tagging and cost visibility from day one

Case studies

Placeholder Rebuilding a hand-configured cloud account as code Terraform · Networking · Environments
Problem
Production had been built by hand over several years. Nobody could say what every resource was for.
Approach
Inventoried the account, rewrote it as Terraform modules, and split staging from production.
Outcome
Every change goes through code review, and the environment can be rebuilt from the repository.
Stack
Terraform, AWS VPC, EC2, S3
S-03

Cloud security

Find the misconfigurations before someone else does — public storage, open ports, over-broad keys, missing logs — and fix them in priority order.

  • Configuration review against cloud security baselines
  • Prioritized findings with clear fixes
  • Audit logging and guardrails to prevent repeats

Case studies

Placeholder Security posture review and remediation for a small SaaS team Posture review · Remediation · Guardrails
Problem
The team had grown fast and wasn't sure what was exposed in their cloud account.
Approach
Ran a configuration review, ranked findings by real-world risk, fixed the critical ones together, and added guardrails.
Outcome
Public exposure closed, audit logging turned on account-wide, and a short list of remaining work with owners.
Stack
AWS Config, CloudTrail, IAM Access Analyzer
S-04

Identity & access management (IAM)

Most breaches start with an account. We make sure every person has one identity, strong authentication, and access that ends the day they leave.

  • Single sign-on and enforced multi-factor authentication
  • Joiner, mover, and leaver procedures
  • Removal of shared and orphaned accounts

Case studies

Placeholder Identity cleanup and single sign-on rollout SSO · MFA · Offboarding
Problem
Staff had separate passwords for every app, several shared logins, and former employees still had access.
Approach
Moved apps behind single sign-on, enforced MFA, retired shared accounts, and wrote an offboarding checklist.
Outcome
One identity per person, and access removal handled in one place.
Stack
Microsoft Entra ID, SAML/OIDC
S-05

Role-based access control (RBAC)

Access based on job function, not on who asked last. We design roles, map them to permissions, and set up reviews so access doesn't drift.

  • Role model mapped to real job functions
  • Least-privilege permission matrix
  • Recurring access reviews with sign-off

Case studies

Placeholder Role model for an internal records application RBAC · Least privilege · Access review
Problem
Everyone in the application was effectively an administrator.
Approach
Interviewed each team, defined roles from what they actually needed, built a permission matrix, and migrated users onto it.
Outcome
Administrative access limited to the people who need it, with a scheduled access review.
Stack
Application-level RBAC, PostgreSQL row-level security
S-06

Governance, risk & compliance (GRC)

Security you can prove. We measure systems against CIS Benchmarks, map controls to the NIST Cybersecurity Framework and NIST SP 800-53, and turn the gaps into a plan you can act on.

  • CIS Benchmark hardening and configuration scans
  • NIST gap assessment and risk register
  • Policies written for how your company really operates

Case studies

Placeholder CIS baseline and NIST CSF gap assessment CIS Benchmarks · NIST CSF · Risk register
Problem
A customer questionnaire asked how the company aligned with NIST, and there was no good answer.
Approach
Scanned servers and workstations against CIS Benchmarks, mapped existing controls to NIST CSF functions, and logged the gaps as risks.
Outcome
A prioritized remediation roadmap and a written answer the company could stand behind.
Stack
CIS-CAT, NIST CSF 2.0, risk register

§04 — Engagement

For clients

How a project runs

No surprises. You see the scope and the price in writing before any work starts, and you own everything we build.

  1. 01

    Scope call

    A short call to understand the problem, the systems involved, and what done looks like.

  2. 02

    Written proposal

    Fixed scope, deliverables, timeline, and price. Nothing starts until you sign off.

  3. 03

    Build & harden

    Work in short increments with regular check-ins. Security is part of the build, not a later phase.

  4. 04

    Handover

    Documentation, runbooks, and credentials transferred to you. Ongoing support if you want it.
